## 1. 为什么需要 v1

v0 只定义了"字段长什么样"，没有定义"语义"。实际做下来发现 5 个洞，每一个都会让下游没法干活：

| # | v0 的问题 | 谁会卡住 |
| --- | --- | --- |
| 1 | 只有投票行，没有**事件**（上线 / 离线 / 网关心跳） | 后端分不清「没人投票」和「网关挂了」 |
| 2 | 没有**在线集合**，`devices_online` 只能靠猜 | 前端「设备在线数量」做不出来 |
| 3 | 二进制包用 `char vote[16]` 存三个枚举值 | 21 字节/包，比较要按定长 `strncmp`，容易出边界 bug |
| 4 | 没有**协议版本号** | 以后改字段无法平滑过渡，也没法拒绝旧包 |
| 5 | 定义了 `sequence` 但没用起来 | 丢包、重复投递都检测不到 |

v1 的目标不是加功能，是**把"设备状态"这件事说清楚**——让前端能回答"现在有几个学生在连"。

## 3. 段一：学生端 → 网关（ESP-NOW 二进制）

```c
typedef struct {
    uint8_t  ver;       /* 协议版本，当前 = 1 */
    uint8_t  node_id;   /* 1..8 */
    uint8_t  vote;      /* 0=UNDERSTAND 1=UNSURE 2=NOT_UNDERSTAND 3=HEARTBEAT */
    uint32_t sequence;  /* 该节点自增 */
} __attribute__((packed)) vote_packet_t;
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ver` | uint8 | 必须 = 1，否则网关丢弃并计入 `bad` |
| `node_id` | uint8 | 1..8，0 和越界值会被丢弃 |
| `vote` | uint8 | 0/1/2 为投票，3 = 心跳（只刷新在线状态，不计票） |
| `sequence` | uint32 | 每发一包 +1，网关用它去重 |

**长度从 21 字节降到 7 字节**，且不再需要 `strncmp` 按定长比较字符串。

⚠️ **两端必须完全一致**：结构体必须带 `__attribute__((packed))`，否则编译器会插入对齐填充，两端算出的长度不同、字段错位（表现为 `node_id` 读出天文数字）。

## 4. 段二：网关 → PC（USB 串口，JSON Lines）

一行一条 JSON，以 `\n` 结尾。**三类事件，用 `t` 字段区分**：

### 4.1 `vote` —— 一张投票

```json
{"t":"vote","node":1,"vote":"UNDERSTAND","seq":42,"rssi":-57}
```

### 4.2 `node` —— 节点上线 / 离线

```json
{"t":"node","node":1,"online":true,"count":42}
{"t":"node","node":3,"online":false,"count":128}
```

上线事件在网关第一次看到该 node_id 时发一次；离线事件在 **5000 ms 没收到该节点任何包**时发一次。

### 4.3 `gw` —— 网关心跳（1 Hz）

```json
{"t":"gw","uptime":3600,"rx":1200,"drop":0,"bad":0,"online":[1,2],"ch":1}
```

| 字段 | 含义 |
| --- | --- |
| `uptime` | 网关运行毫秒数 |
| `rx` | 累计有效投票数 |
| `drop` | 因 sequence 重复丢弃的包数 |
| `bad` | 长度 / 版本 / 取值非法的包数 |
| `online` | **当前在线节点列表** ← 前端的「设备在线数量」直接取这个长度 |
| `ch` | ESP-NOW 信道 |

### 4.4 解析规则（给 PC 端）

1. 只处理以 `{` 开头的行，其余是 ESP-IDF 日志，跳过
2. 按 `t` 分发；**遇到不认识的 `t` 应当跳过而不是报错退出**（为后续演进留余地）
3. 没有 `t` 字段的行按 v0 纯投票行处理（向后兼容）

### 4.5 在线判定的依据

ESP-NOW 是**无连接**的：没有握手、没有断开通知。板子断电，网关收不到任何信号。所以在线状态只能靠"最近有没有收到包"反推：

- 收到任意包（投票或心跳）→ 刷新 `last_seen`
- 超过 5000 ms 没有任何包 → 判离线，发一次 `online:false`

**这就是为什么最好让学生端发心跳**：没有心跳的话，一个学生安静坐着不按键，5 秒后就会被误判为离线，在线人数会乱跳。

这一段由后端决定（也是我），本期不随 v1 改动。前端继续用任务书第 4 节的 Mock 格式，我们只在后端把串口事件聚合成那个格式。

## 6. 命名约定：大小写怎么统一

v0 里存在一个已知冲突：串口层用大写 `UNDERSTAND`，前端 Mock 用小写 `understand`。

v1 的约定是**分层处理，不强行统一**：

| 层 | 用法 | 理由 |
| --- | --- | --- |
| ESP-NOW 二进制 | 枚举 0/1/2 | 不需要字符串 |
| 串口 JSON | 大写 `UNDERSTAND` | 与任务书第 2 节一致，便于人眼核对 |
| HTTP 接口 | 小写 `understand` | 与任务书第 4 节的前端 Mock 一致 |

映射只在 backend 里做**一次**，两端都不用记两套。

## 9. 怎么验证（现在就能跑）

网关已经实现 v1。用 mock 模式，**一块板就能看到全部三类事件**：

```powershell
# 1. 打开 mock 开关（sdkconfig 不入库，本地配置）
#    idf.py menuconfig -> ThreeKeyVoter Gateway -> 网关自产 Mock 数据
cd firmware\gateway
idf.py build
idf.py -p COM5 flash

# 2. 另一端
python backend\read_serial.py --port COM5 -v
```

预期现象：

1. 启动后立刻出现 3 条 `node 上线` 事件
2. 每秒 3 条 `Node N: VOTE`
3. **第 20 秒**，第 3 个节点停止发数据，5 秒后（约第 25 秒）出现 `[离线] Node 3`
4. 输出的 `[网关]` 心跳行里 `online` 列表从 `[1, 2, 3]` 变成 `[1, 2]`

第 3、4 条就是 v0 做不到的事情。
